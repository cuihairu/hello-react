# 发展史时间线

React 的每个大版本都是对上一个时代痛点的回答：2013 年开源，回应的是 MVC 时代手动同步状态的脆弱；2016 年公开 Fiber，回应的是递归 diff 卡死帧预算；2018 年的 Hooks，回应的是类组件复用逻辑的嵌套地狱；2020 年的 React 17 什么特性都没有，却在为多版本共存修地基。这条线按时间顺序排列 {{ TIMELINE.length }} 个节点，每个节点都先回答同一个问题：为什么是这个时候。

## 这条线怎么读

**先分期，再筛选。** 页面把十六年切成四个 Era：萌芽与开源（2010 至 2015）、重写内核（2016 至 2019）、并发与服务器（2020 至 2024）、编译器时代（2025 至今天），每个 Era 有一句导语交代当时的主要矛盾。顶部的主题标签——核心版本、并发与渲染、生态与工具、走向未来——把同一条线拆成四条线索，计数标在标签上；筛到只剩一组时，同一时期的取舍会看得更清楚：只看「并发与渲染」，就能从 2016 年的 Fiber 公开一路读到 2025 年 Activity 落地，一条九年的长线。

**点开读来由。** 每个节点收起时只有年份、标题与提出者，点开后的详情回答两件事：它回应了什么痛点，以及站内哪一章展开讲它。多数节点都能跳进本站的正文章节，读完年表再进正文，或读正文时回头对位年表，两条路径都通。

**需要通读时**，页面底部「按时期通读全部节点」那一段是同一份数据的文本形态，不依赖交互，也便于逐条对照正文各章。

## 关于这份数据的口径

年份取的是「宣布或发布」的时点，不是它被广泛接受的时点：Hooks 在 2018 年 10 月的 React Conf 上预览，2019 年 2 月才随 16.8 稳定；Server Components 2020 年 12 月首演，规模化落地要等到 Next.js App Router。所以这条线标出的是「方向被公开承诺」的时刻，共识的形成通常还要再等一两年。各节点的技术细节与本站正文（如[发展历程与核心理念](/typescript-react/react-history-principles)、[React Fiber 架构详解](/architecture/react-fiber)、[React 的未来](/future/react-future)）口径一致，冲突时以正文为准。
